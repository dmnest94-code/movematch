# MoveMatch SF v4 — пошаговая инструкция

**Это новая версия, НЕ опубликованная в GitHub и Netlify.** Действующая версия не менялась. Перед заменой обязательно сохрани её резервную копию. Файлы живой версии v3 получить не удалось; доступен только старый MVP, поэтому проверь, не было ли на v3 функций, отсутствующих здесь.

## Часть 1. Сначала проверь сам сайт

1. Распакуй архив `MoveMatch_SF_v4_website.zip`.
2. Открой `index.html` в браузере. Для полноценного отображения (из-за абсолютных путей `/assets/...` и `/js/...`) лучше запустить локальный сервер в распакованной папке: `python -m http.server 8080`, затем открыть `http://localhost:8080`.
3. Нажми «Find my move style»: выбери `My home`, пройди форму и проверь предложенный Residential Style.
4. Нажми «Request an on-site estimate»: здесь нужно выбрать/проверить размер офиса, указать адрес для выезда и предпочтительную дату визита. **Офис = ТОЛЬКО on-site estimate.**
5. В локальной версии кнопка отправки сознательно НЕ имитирует успешное получение заявки: для реальной отправки нужен Netlify.

## Часть 2. Поменять свой номер и публичную почту

1. Открой `js/config.js`.
2. Заполни точно три строки:

```javascript
phoneDisplay: "(415) 555-0123",  // ЗАМЕНИ на свой номер в красивом формате
phoneE164: "+14155550123",     // ЗАМЕНИ на свой номер в международном формате
email: "hello@example.com",   // ЗАМЕНИ на свой рабочий email
```

3. Сохрани файл. Если хочешь, чтобы изменения появились на живом сайте, обнови его в GitHub (и Netlify заново опубликует версию).
4. Ссылки на пустые контакты НЕ показываются на сайте. Настоящий номер и почту нужно указать самому; шаблонные значения в архиве пустые, а примеры выше — НЕ настоящие контакты.

## Часть 3. Поменять адрес, куда приходят ЗАЯВКИ

**Важно: это НЕ `js/config.js`.**

1. Открой https://app.netlify.com и выбери проект MoveMatch.
2. Перейди в **Forms**. Если form detection выключен, включи его и заново опубликуй сайт.
3. После загрузки новой версии проверь наличие формы **`move-request`**.
4. Перейди в **Forms → Submission notifications** (иногда из настроек формы).
5. Добавь или отредактируй уведомление типа **Email notification**. В качестве получателя укажи нужную новую почту.
6. Удали старое уведомление (если больше не нужно), сохрани настройки.
7. Отправь через опубликованный сайт две тестовые заявки: residential и office. Проверь, что каждая появилась в Netlify Forms, и что уведомление пришло на нужную почту. Не полагайся только на экран «Спасибо».

## Часть 4. Как безопасно обновить GitHub / Netlify

Вариант без командной строки — GitHub Desktop (https://desktop.github.com):

1. Открой свой репозиторий MoveMatch на GitHub и нажми **Code → Download ZIP**, чтобы сохранить резервную копию живой версии.
2. Установи/открой GitHub Desktop → **File → Clone repository**, выбери свой репозиторий.
3. В GitHub Desktop создай новую ветку, например `movematch-v4-preview` (**Branch → New branch**). Не изменяй сразу `main`.
4. Нажми **Repository → Show in Explorer/Finder**, чтобы открыть локальную папку репозитория.
5. Сверь, где находится публикуемый Netlify каталог. Если Netlify сейчас публикует корень репозитория (`.`), скопируй туда распакованные `index.html`, `assets`, `js`, `privacy.html`, `success.html`, `netlify.toml`. Если сайт публикуется из другой папки, используй именно её.
6. В GitHub Desktop проверь список изменённых файлов. Не удаляй неизвестные файлы и интеграции старой версии без проверки.
7. Сделай **Commit to movematch-v4-preview → Publish branch**.
8. В Netlify проверь, появился ли Deploy Preview для ветки. Если previews отключены, включи их в настройках деплоя или создай отдельный тестовый сайт (не заменяй продакшен).
9. На Deploy Preview проверь мобильную версию и отправь тестовые заявки. Для форм может потребоваться включить Form detection и сделать новый деплой.
10. Когда всё проверено, открой pull request в GitHub и объедини с production-веткой. После публикации повтори тест формы на живом домене.

## Часть 5. QR-коды

- `qr/qr-business-card.svg` — для визиток.
- `qr/qr-business-card.png` — PNG с белым фоном для печати.
- `qr/qr-headrest-sign.svg` и `.png` — для таблички в машине.

Они ведут на адрес:
- Визитка: `https://movematchsf.com/?utm_source=uber&utm_medium=print&utm_campaign=business_card`
- Табличка: `https://movematchsf.com/?utm_source=uber&utm_medium=print&utm_campaign=headrest_sign`

**Внимание:** в этой сессии домен не удалось открыть/подтвердить. Это корректно закодированные QR, но **не печатай тираж, пока реально не отсканируешь их и не увидишь работающий сайт с формой**. Если адрес изменится, QR нужно пересоздать. Используй SVG для типографии и оставь белую зону вокруг.

## Часть 6. Финальная проверка перед рекламой в Uber

- Домен открывается с телефона, форма отправляется в Netlify, получатель почты правильный.
- Текст на сайте согласован с тем, что MoveMatch действительно предоставляет; ни один блок не обещает несуществующих партнерств, цен или гарантированных услуг.
- Для офисных переездов форма ВСЕГДА требует on-site address + date, и следующий шаг только on-site estimate.
- Проверено, нужна ли MoveMatch лицензия/разрешение в Калифорнии для рекламы, организации, привлечения клиентов/брокерских услуг в сфере residential moving. Закон CA BPC §19237 и правила BHGS могут распространяться на рекламу и организацию перевозок; даже правильный дисклеймер не заменяет разрешение. Проверку проведи ДО печати табличек и запуска клиентских заявок.
- Обнови текст политики конфиденциальности (`privacy.html`) по фактическим процессам компании.
